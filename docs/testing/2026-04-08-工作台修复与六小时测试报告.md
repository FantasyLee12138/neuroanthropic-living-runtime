## 二、问题背景

在修复前，工作台存在两类关键问题：

1. `console/talk`、`console/endogenous/tick`、`web/session/event` 等重请求会直接在 observer 的请求线程中执行重逻辑。
2. 一旦这些请求进入执行，整个站点会出现明显的“看似运行中，但所有页面和接口一起卡死”的现象。

当时实际复现到的现象包括：

- `POST /console/talk` 发出后，请求可长时间不返回
- 该请求执行期间，`/dashboard`、`/console/state`、`/autonomy/status` 会一起超时
- 浏览器表现为：
  - 主体控制显示运行中
  - 认知工作台、概率与坍缩、表达通道等区域长时间没有更新
  - 用户体感上就是“卡住，没有下一步动作”

## 三、根因定位

根因不在前端渲染，而在 observer API 的执行模型：

- 重请求虽然声明为 `async` 路由，但内部直接同步调用运行时和 terminal handler
- 这些同步调用会占住事件循环所在执行路径
- 结果是当前请求没完成时，其他轻量只读请求也无法及时返回

进一步看，`web/session/event` 的 `user_turn` 还有第二层问题：

- 它原先要等整轮用户输入处理完成后才返回 HTTP 响应
- 在 live 环境下，这会让工作台的“发送消息”动作本身变成高时延阻塞点
- 这和工作台应该“先接纳、再后台处理、结果走 SSE/状态刷新”的交互模式不匹配

## 四、修复内容

本次修复采用的是最小但有效的收敛方案，没有改动 TLH runtime 的基本语义，只调整 observer 层的执行方式。

### 1. observer 重路径移出事件循环

在 [services/observer/api/app.py](/Users/fantasylee/类脑架构/services/observer/api/app.py) 中新增了串行 runtime 执行辅助：

- 使用 `threading.RLock()` 保护 controller / terminal handler 的共享可变状态
- 使用 `asyncio.to_thread(...)` 将重请求转移到 worker thread 中执行

受影响并完成收敛的路径包括：

- `/console/talk`
- `/web/session/start`
- `/web/runtime/start`
- `/web/runtime/pause`
- `/web/runtime/resume`
- `/web/runtime/wake`
- `/web/session/event`
- `/console/endogenous/tick`
- `/autonomy/start`
- `/autonomy/stop`
- `/autonomy/step`
- `/persona/reset`
- `/endogenous/tick`

### 2. autonomy 后台循环与请求路径共享同一串行锁

observer 的 autonomy heartbeat 线程也被纳入同一串行执行保护，避免：

- 请求线程与 autonomy 线程同时写 runtime
- 导致工作台状态与运行时状态产生新的竞争问题

### 3. `user_turn` 改为即时接纳

在 [services/observer/api/app.py](/Users/fantasylee/类脑架构/services/observer/api/app.py) 中，`/web/session/event` 的 `type=user_turn` 被改为：

- 立即返回 `accepted: true`
- 后台线程继续执行真正的 turn 处理
- 处理结果继续进入 event broker

这一步是工作台交互体验修复的关键，因为它把“输入接纳”从“整轮完成后才返回”改成了“先接纳，再后台继续处理”。

### 4. SSE `once=true` 语义修正

在 [services/observer/api/web_sessions.py](/Users/fantasylee/类脑架构/services/observer/api/web_sessions.py) 中，调整了 broker 的 `once=true` 行为：

- 以前是“如果当前没有事件就立刻返回空”
- 现在是“等待到新事件或超时”

这让后台派发后的前端轮询与 SSE 语义重新一致。

### 5. 前端接入新的 `last_event_id` 基线

在 [services/observer/dashboard/index.html](/Users/fantasylee/类脑架构/services/observer/dashboard/index.html) 中，对以下操作补了 `last_event_id` 追踪：

- `control_command`
- `user_turn`
- `approve`

作用是：

- 在请求已被接纳但结果尚未生成时，前端不会错误地把旧事件重新当作新结果

### 6. 后续残留问题收敛修复

在 [services/observer/api/app.py](/Users/fantasylee/类脑架构/services/observer/api/app.py) 中，`2026-04-08` 又补了一轮最小收敛：

- 后台 `user_turn` 不再持有全局 `runtime_lock` 跑完整条对话链路
- 改为按 `session_id` 单独串行，避免 `observer-main` 前台对话把整套 runtime 写路径一起堵死
- `observer-main` 有前台对话在跑时，autonomy heartbeat 会直接让路，不再插队竞争
- `/console/endogenous/tick` 与 `/endogenous/tick` 在该场景下会快速返回 `skipped=true`，不再等待前台对话执行完成
- `skip` 分支返回轻量 `console` 载荷，避免“逻辑已跳过但仍计算整份重快照”
