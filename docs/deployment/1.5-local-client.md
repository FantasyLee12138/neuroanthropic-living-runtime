# NALR 1.5 Local Client Deployment

## 目标

1.5 的本地客户端以 `Open_NALR_Workbench.command` 为正式入口。当前实现是“桌面 `.app` 壳 + bundle 内 observer/runtime 服务 + 浏览器 workbench”，而不是独立原生 UI。

## 启动链

1. 双击 `Open_NALR_Workbench.command`
2. 启动器转发到 `alive-observer start`
3. `alive-observer` 解析 `.env.local` / `.env`
4. `nalr.observer_launcher` 拉起后台服务
5. 服务就绪后打开 `/dashboard`

## 打包当前客户端

当前仓库提供一个 bundle-contained `.app` materializer：

```bash
python3 /Users/fantasylee/类脑架构/scripts/local_client_packager.py dist
```

默认会生成：

```text
dist/NALR Local Client.app
```

当前 bundle 会把以下内容 materialize 到 `Contents/Resources/app`：

- `src`
- `services`
- `config`
- 可复用 `.venv`（若存在）

生成的 `alive-observer` 会优先从 bundle 内 runtime 启动，并把服务状态目录落到用户可写位置，而不是写进 `.app` 内部。

## 本地交付要求

- 冷启动成功
- 重复启动不产生脏状态
- `alive-observer status` 可读
- `alive-observer logs` 可读
- `alive-observer stop` / `restart` 可用
- `.alive` 运行目录在升级后仍可恢复
- 重复 materialize 不残留旧 bundle 脏文件

## 验收命令

```bash
zsh /Users/fantasylee/类脑架构/Open_NALR_Workbench.command --help
/Users/fantasylee/类脑架构/alive-observer start --no-browser
/Users/fantasylee/类脑架构/alive-observer status
/Users/fantasylee/类脑架构/alive-observer logs
/Users/fantasylee/类脑架构/alive-observer stop
```

- 安装器、签名、公证与跨平台分发不属于当前交付范围
