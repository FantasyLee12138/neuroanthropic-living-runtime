# NALR 1.6 Acceptance Plan

## Goal

把 `1.6` 收敛成一个可发布版本：Workbench 默认前台不再依赖旧多接口拼接，`subject / meaning / agency` 成为真实运行时闭环，分析页进入中文优先、单主阅读流的前台形态，并且从 `Open_NALR_Workbench.command` 打开时能看到最新前端产物。

## Acceptance Principles

- 必须符合 TLH、架构宣言和 `PLAN1.6.md` 的主体性优先方向
- 根目录只保留 `README.md`、`架构宣言.md`、`PLAN1.6.md` 三份活文档，其余 root markdown 全部归档
- 必须先保证前台读到 runtime 真相，再谈页面风格和术语优化
- 必须提供自动化或可复现证据，不能只靠截图和主观描述
- 必须把“最新 Workbench 产物可达”纳入 front door 验收，而不是默认人工构建

## Release Gate

- `release_frontdoor` 必须 `pass`
  覆盖 `Open_NALR_Workbench.command -> observer dist sync -> /dashboard -> /workbench/read-model -> /workbench/round/{id}` 这条前台入口链。
- `release_subjectivity` 必须至少达到 bounded `pass`
  覆盖 `release_16.subjectivity.single_truth`
  覆盖 `release_16.subjectivity.memory`
  覆盖 `release_16.subjectivity.competition`
  覆盖 `release_16.subjectivity.history`
  覆盖 `release_16.subjectivity.recovery`
  覆盖 `release_16.subjectivity.drift`
- P1 项完成率达到 90% 以上，且没有阻塞级 fail
- Workbench 前台、runtime 闭环、文档三条线口径一致
- 已有 bounded acceptance 证据；真实 24h soak 仍允许保持 `partial`，但必须明确记录为未完成

## Acceptance Layers

### P0 Front Door

这组条目统一属于 `release_frontdoor`。

- `Open_NALR_Workbench.command` 双击后打开 `/dashboard`
- observer 启动前会自动同步 `apps/workbench/src -> apps/workbench/dist`，不再要求手动 build 才能看到最新页面
- `/dashboard` 默认进入新的 Workbench，旧页仅保留在 `/dashboard-legacy`
- `/workbench/read-model` 与 `/workbench/round/{id}` 可读

### P1 Runtime Truth

这组条目不再单独代表 `1.6` 完成，而是并入 `release_subjectivity` 的证据面。

- Workbench 不再回退到旧多接口拼接路径
- `subject / meaning / agency` 通过真实 runtime 状态进入总览页
- `purpose_memory`、`meaning_system`、`subject_kernel`、`agency_loop` 在计划任务和当前目标之间形成闭环
- 自治在有到期计划任务时优先执行计划任务，而不是退回通用 `self_run / nothing`

### P0 Subjectivity Gate

`release_subjectivity` 固定验收六个 namespace：

- `release_16.subjectivity.single_truth`
  证明 `单一真相源` 的四层真相架构成立：`Event Log / Authoritative State / Snapshot / Projection`。
- `release_16.subjectivity.memory`
  证明记忆是 `不完美结构性记忆`，而不是外挂检索；必须覆盖 miss、cue rescue、summary contamination、latency/cost。
- `release_16.subjectivity.competition`
  证明竞争与仲裁是可追踪机制；必须覆盖 competing proposals、winner、rejected options、budget、consequence patch。
- `release_16.subjectivity.history`
  证明 `历史不可逆负担` 会沉积为 `history_burden`，成为后续轮次的真实负担。
- `release_16.subjectivity.recovery`
  证明 restart、checkpoint/rewind、reattach 后连续性与负担面仍能恢复。
- `release_16.subjectivity.drift`
  证明 bounded long-run 会继续观测 distortion、history inertia、continuity recovery 和 arbitration consequence。

### P1 UX And Reading Flow

- 总览页先回答“稳不稳、为什么继续、下一步看哪层”
- 分析页固定为左侧轮次筛选、中间主阅读流、右侧证据抽屉
- 中文界面默认不暴露 `Workbench / Safe Mode / posterior / why-not / raw JSON` 等英文主标签
- 关键断点 `375 / 768 / 1024 / 1440` 无横向溢出

### P2 Hardening

- self-hosted / bounded acceptance 文档与 1.6 现状对齐
- release notes 明确新增能力、前台变化、兼容性和残留风险
- 24h soak、长期运维和更深的 Hermes-inspired 调度治理继续保持在后续 hardening 阶段

## Manual Acceptance

- 双击 `Open_NALR_Workbench.command`
- 确认首页标题为“`NALR 运行工作台`”，而不是旧的英文 Workbench 首屏
- 在总览页看到主体、意义、主动闭环和最近轮次四块核心区
- 进入分析页，确认存在左侧轮次区、中间主阅读流、右侧证据区
- 切换到设置页，确认看到计划任务区和危险区解锁门
- 如需回退旧页，只能通过 `/dashboard-legacy`
- 读取 `acceptance_report.release_16.release_frontdoor`
- 读取 `acceptance_report.release_16.release_subjectivity`
- 运行 `scripts/acceptance_16.py --emit-report --window 16`，确认 bounded subjectivity evidence 返回 `pass`
- 确认 `state_truth / memory_evidence / competition_evidence / continuity_evidence` 在 read-model 与 round detail 中可见

- 本计划不声称 Hermes-inspired skills / cron 治理已经全部交付
- 本计划不声称 1.5 ledger 已被整体迁移到 1.6 ledger；当前以新增 release docs 为主
