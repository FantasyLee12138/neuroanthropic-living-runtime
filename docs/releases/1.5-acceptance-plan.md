# NALR 1.5 Acceptance Plan

## Goal

把 TLH runtime、workbench、terminal、launcher、self-hosted service、bounded long-run acceptance report 和 controlled learning policy surface 收敛成一个可以发布的 `1.5`。

## Acceptance Principles

- 必须符合 TLH、架构宣言和 frozen substrate 的底线
- 必须对用户可达，不是代码存在即可
- 必须有自动化、脚本化或可复现证据

## Release Gate

- P0 / P1 完成率达到 90% 以上
- 没有阻塞级 fail
- local client、self-hosted service、bounded acceptance report、acceptance docs 三条交付线都可用

## Acceptance Layers

### P0 Delivery

- `Open_NALR_Workbench.command` 可双击打开
- `alive-observer start` 可拉起服务并暴露 `/service/status`
- workbench 的 state / why / why-not / initiative / monologue 可用
- 单实例服务端具备启动、停止、重启、日志和状态探测能力

### P1 Consistency

- terminal / dashboard / observer API 收敛到同一 read-model
- autonomy / initiative / monologue 状态一致
- route taxonomy、权限模型、文档口径一致
- trace / replay / diagnostics 可解释

### P2 Enhancements

- 长时 soak 与预算报告
- 桌面分发增强
- 计划性学习策略与运维增强

## Controlled Learning Gate

- 默认学习模式是 `guided-learn`
- observer settings 与 runtime state 都暴露学习模式、allowlist 域名、可写目录、知识目录、学习日志目录和 trace 开关
- 外部学习必须可被 observer 和 terminal 观测
- 任何越权、预算失控或异常都必须能被 safe mode / breaker / rollback 截断
