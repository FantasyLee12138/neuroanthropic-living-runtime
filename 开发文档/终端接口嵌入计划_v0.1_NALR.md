# NALR 用户输出压缩与显隐分层改造计划

## Summary
- 目标改成：`NALR` 默认表现为**普通用户助手**，而不是 debug console。默认只显示用户输入和最终 assistant 回复，不再暴露 `Run / Step / Tool / Session` 事件流。
- 交互策略锁定为：
  - 默认输出：**只显示最终回复**
  - 细节入口：**仅在 slash 命令时显示**
  - 问候/寒暄：**直接自然回复，不启动 run**
  - 仓库任务：**默认自然助手回复，不主动暴露内部步骤**
  - 细节格式：**人类可读摘要，不直接展示 JSON**
- 不改变底层 `.alive`、trace、observer、`alive` operator 能力；只改变 `NALR` 的**回合判定、事件显隐、面板渲染和 one-shot 输出策略**。

## Key Changes
### 1. Turn 路由从“全部 run”改成“双路径”
- 在 `src/nalr/terminal_bridge/handlers.py` 增加 `turn_kind` 判定：
  - `direct_chat`
  - `task_run`
- `direct_chat` 规则固定为：
  - 短问候、寒暄、感谢、确认、无仓库意图的简短输入
  - 不启动 `start_run`
  - 直接走 `RuntimeController.tick(... scenario="chat", mode="interactive")`
  - 只回传一个 `assistant_final`
- `task_run` 规则固定为：
  - 提到仓库、代码、文件、目录、trace、bug、test、fix、read、search、analyze、explain code 等任务意图
  - 继续走现有 `start_run` 只读闭环
  - 但默认只回传一个**自然语言 assistant 回复**
  - `run_status / steps / tools / why` 只保留在状态缓存和 slash 详情里，不进入默认可见输出
- 判定策略先用**本地显式启发式**，不引入新模型路由；歧义时优先落到 `task_run`，只有明显寒暄才走 `direct_chat`。

### 2. Bridge 事件从“全量可见”改成“内外分层”
- 保留现有 typed bridge 事件类型，不重做协议。
- 但事件语义改成两层：
  - 内部状态事件：`run_status / step_update / tool_call / tool_result / session_started / session_ended`
  - 用户可见事件：`assistant_final`、必要时的 `error`
- `user_turn` 默认行为：
  - `direct_chat`：仅发 `assistant_final`
  - `task_run`：只发 `assistant_final`
- `assistant_token` 仅在真正实现了逐字/分段流式时才发；当前首发阶段默认**不发**，避免和 `assistant_final` 重复。
- slash 命令行为固定：
  - `/status`：返回当前 run 的人类可读摘要
  - `/why`：返回“为什么当前这么做”的人类可读摘要
  - `/steps`：返回当前/待处理步骤的压缩列表
  - `/tools`：返回最近工具使用摘要
  - `/pause` `/resume` `/abort`：执行控制后只回一条短确认，不输出整包状态事件流
  - `/model`：显示当前启用的 route 摘要，不显示原始 config JSON

### 3. Node UI 从“事件日志”改成“对话主视图 + 隐藏状态缓存”
- `apps/terminal/src/state/sessionStore.ts` 改成：
  - 桥接事件继续更新内部 `run / steps / tools / why` 缓存
  - 但**不再把 system 事件追加到 conversation lines**
- 主对话区只允许 4 类内容进入：
  - 用户输入
  - assistant 最终回复
  - 本地帮助信息
  - 错误信息
- `apps/terminal/src/app.tsx` 改成：
  - 默认主视图只显示 conversation
  - `/status` `/why` `/steps` `/tools` 才打开临时 detail panel
  - detail panel 渲染人类可读摘要，而不是 `JSON.stringify(...)`
- `apps/terminal/src/cli.ts` one-shot 模式改成：
  - 默认只打印 `assistant_final`
  - 不打印 `Run ...` / `Step ...` / `Tool ...`
  - 失败时才打印 `Error: ...`

### 4. 默认文案与摘要策略固定
- `direct_chat` 默认输出风格：
  - 简短、自然、像助手
  - 不提 `run`、`repo_scan`、`tool`、`step`
  - 示例：`你好，我可以帮你看仓库结构、定位文件、解释代码或规划下一步。`
- `task_run` 默认输出风格：
  - 像正常助手的简短回应，而不是内部计划 dump
  - 示例：`我先看一下这个仓库的结构，然后给你一个简明结论。`
- `/why` 摘要固定包含：
  - 当前任务目标
  - 当前选择这一步的原因
  - 如果 paused，暂停原因
- `/status` 摘要固定包含：
  - 当前 run 状态
  - 当前 step 标题
  - 是否 paused / dirty worktree
- `/steps` 摘要固定包含：
  - 当前 step
  - 余下步骤数量
- `/tools` 摘要固定包含：
  - 最近 1-3 个工具名与一句话结果

### 5. 测试与稳定性修正一起纳入
- 自动化测试不再依赖 `.env.local` 的 live model 行为作为前提。
- `NALR` 根脚本增加一个**测试友好开关**，二选一并固定其一：
  - `NALR_SKIP_ENV_AUTOLOAD=1` 时不加载 `.env.local/.env`
  - 或保留自动加载，但测试显式设置 `NALR_ONE_SHOT_TIMEOUT_MS`
- 推荐默认：**增加 `NALR_SKIP_ENV_AUTOLOAD=1`**，并在 terminal 集成测试里启用，确保 one-shot 测试不被 live provider 时延影响。
- `./NALR --help`、one-shot、interactive 都必须在无 live provider 时可用，走现有 Python fallback planner。

## Test Plan
- Python 单元：
  - 问候输入走 `direct_chat`，不创建 run，不调用 `start_run`
  - 仓库任务输入走 `task_run`，会创建 run，但默认只返回 `assistant_final`
  - `assistant_token` 在当前首发模式下默认不发
  - `/status` `/why` `/steps` `/tools` 返回摘要文本，而不是原始 JSON
- Node 单元：
  - `sessionStore` 更新隐藏状态缓存时，不再追加 `System:` 对话行
  - slash parser 保持现有控制命令集合不变
  - one-shot formatter 只输出 assistant/error，不输出 run/step/tool
- 集成：
  - `NALR "你好"` 只输出自然回复，不出现 `Run/Step/Tool/repo_scan`
  - `NALR "总结这个仓库结构"` 只输出最终助手回复，不出现系统事件流
  - `/status` `/why` `/steps` `/tools` 能打开 detail panel，并显示人类可读摘要
  - `alive` 与 observer 仍能读到底层 run/step/tool 数据，证明只是前台隐藏，不是底层丢失
  - `NALR_SKIP_ENV_AUTOLOAD=1` 下 one-shot 集成测试稳定通过
- 验收：
  - 用户在默认路径下不会再看到 `System: Run ... / Tool call ... / Tool result ...`
  - 用户只有在显式请求细节时才看到摘要化的内部状态
  - 问候输入不再触发仓库规划语义

## Assumptions
- 这次改造只压缩 `NALR` 的用户可见输出，不改变 `.alive`、trace、observer、`alive` 的 operator 能力。
- 当前首发阶段不做真正 token 级流式，因此 `assistant_token` 默认关闭。
- `turn_kind` 采用本地启发式分类，不新增模型分类器。
- detail panel 优先做摘要，不做摘要/JSON 双视图。
- 自动化测试默认绕开 live provider 自动加载，保证输出和超时行为可预测。
