# NALR 架构宣言式摘要

## Summary

NALR 不应被整理成一个“为了兼容生态而牺牲自身结构”的普通 Agent 框架。  
它的目标应当是：在内核上坚持类脑、概率化、自我稳定、边界内生、可观测可验证；在外层上提供对主流大模型 API、LangChain、LlamaIndex、向量数据库与工具生态的标准兼容面。

兼容化不是主导思想，内核完整性才是主导思想。  
外部标准接口只能作为接入层，不能反向规定 NALR 应该如何思考、如何记忆、如何形成自我、如何建立边界。

本系统不追求“消除退化”，而是通过概率约束、冲突闭环与长期调节机制，使退化过程可观测、可解释、并在必要时可被逆转或再平衡。

## Core Position

NALR 的核心不是“命令系统”“CLI”“向量库接入器”或“框架适配器”，而是一个类脑概率运行时。

这个运行时必须坚持以下立场：

- 模型自身是动作与表达生成的主体，外层系统不能粗暴接管其最终动作。
- 响应应主要由概率逻辑形成，而不是由大量硬规则拼装。
- 自我不是 prompt 里临时贴上的角色设定，而是持续存在、可积累、可追踪、可约束输出分布的稳定先验核。
- 边界不是外部审查阀门，而是 identity、relationship、authenticity、long-run value 在概率场中的内生成分。
- 记忆不是外挂文本仓库，而是参与生成、影响注意力、调节分布的再激活系统。
- 冲突不是模板化异常处理，而是多峰候选之间的真实仲裁机制。
- 真实性与生命性不是装饰层，而是运行时长期一致性的组成部分。

因此，NALR 的正确方向不是“把现有内核压扁到主流框架抽象里”，而是“让主流框架能够接入这个内核，而不破坏它”。

## Compatibility Doctrine

NALR 应兼容主流生态，但兼容的方式必须是单向的、外层的、适配性的。

应坚持以下兼容原则：

- 对 OpenAI 风格 API 的兼容，应是对外暴露标准消息、流式输出、工具调用和模型描述接口。
- 对 LangChain、LlamaIndex 的兼容，应是提供可插拔的 model / retriever / tool adapter。
- 对向量数据库的兼容，应是 projection、索引与检索加速，而不是替代内核记忆。
- 对工具生态的兼容，应是标准工具协议映射，而不是让外部工具系统绕过 NALR 的 policy、trace 与 runtime 边界。
- 对 CLI、终端、observer、API gateway 的整理，应让它们共享统一内核 contract，而不是各自维持一套事实体系。

兼容层的责任是翻译，不是裁决；是接入，不是统治；是暴露能力，不是重写能力。

## Non-Negotiables

以下原则不可退让：

- 绝对不能让外部框架接管 NALR 的核心编排权。
- 绝对不能为了兼容生态而干涉模型自身动作生成。
- 绝对不能把概率响应收缩成规则驱动的机械输出。
- 绝对不能把边界实现成纯外部硬限制，而失去“自我认识中的边界”。
- 绝对不能让外部数据库、框架 memory 或 adapter 取代 canonical runtime state。
- 绝对不能让 compatibility layer 绕过 trace、policy、safe-mode、approval、repair 等运行时主链。
- 绝对不能把 NALR 降级成“一个披着类脑概念外衣的普通 agent 壳”。

## Implementation Direction

因此，后续整理应采取这条路线：

- 内部继续收敛为统一的 probabilistic kernel。
- 自我、边界、关系、记忆、冲突、真实性、生命性继续作为内核先验和分布贡献者存在。
- `.alive`、trace、memory、runtime controller 保留为 canonical evidence chain。
- 对外新增 OpenAI-compatible gateway 与 Python adapter 层。
- 所有生态兼容都建立在 kernel contract 之上，而不是直接连接内部细节。
- 所有兼容工作都必须证明：它增强了接入能力，但没有削弱 NALR 的类脑性、自我一致性和概率自治。

## Assumptions

- 兼容化的目标是降低接入门槛，不是替换内核哲学。
- NALR 的独特性来自其概率化类脑结构，而不是来自自定义 CLI、自定义存储或自定义命令本身。
- 真正应被标准化的是“外部接口”，而不是“内部认知逻辑”。
- 若某项兼容改造要求牺牲模型自治、自我先验、边界内生或 canonical runtime，则该改造应判定为越线。

# NALR v0.57 概率场全量切换计划

## Summary

先把 [`NALR_v0.57_architecture.md`](/Users/fantasylee/类脑架构/NALR_v0.57_architecture.md) 归类成 3 层工作对象，并据此做一次性大改：

- **待做事情**
  - 把现有串行 `stage -> sampled_action` 主链，改成 `context / memory / action / token` 四层共享概率场。
  - 把全部心理模块从“流程节点”改成“概率贡献器”，统一产出 bias / mask / posterior。
  - 把 trace / observer / why / counterfactual 从“流程解释”改成“概率贡献解释”。
  - 把 Dream / Identity / Authenticity / Vitality 从附属 shaping 逻辑改成在线先验与离线再校准系统。
- **模块分类**
  - 核心器官：`Thalamus`、`PFC`、`Hippocampus`、`ConflictMonitor`、`Identity`、`Authenticity`、`Vitality`、`Dream`
  - 在线偏置头：`Emotion`、`Body`、`Relationship`、`Resource`、`Habit`、`Desire`、`DMN`、`Perspective`、`Value`
  - 基础设施：`RuntimeController`、`SkillExecutor`、`BehaviorPlausibilityGuard`、`OutputGate`、`Renderer`、`TraceStore`、observer API
- **方法/机制分类**
  - 路由类：`attention_bias`、memory prior、tool affordance prior、state bias
  - 重打分类：`delta_logits`、`delta_energy`、soft/hard mask、winner posterior
  - 仲裁类：多峰检测、KL/JS 峰值比较、compromise reweighting
  - 先验类：identity prior、authenticity penalty、vitality modulation、dream recalibration
  - 观测类：stacked contribution、counterfactual peaks、suppression cause、module heatmap

本次按你的选择定义为**一次性切换**：不保留 v0.56 trace/observer 兼容层，所有模块在同一改造线内完成概率化；但 **v0.57 最终态** 必须重新满足 v0.56 的 typed contract、显隐性边界、可降级/可回退、可观测、safe mode/fault guard 等工程原则。

## Key Changes

### 1. 运行时与公共接口换代
- 以 [`src/nalr/schemas/models.py`](/Users/fantasylee/类脑架构/src/nalr/schemas/models.py) 为中心，废弃 `AgentContribution` 为核心观察结构的旧模型，新增：
  - `ProbabilisticContribution`
  - `ProbabilityLayerState`
  - `ProbabilityFieldSnapshot`
  - `TokenContributionTrace`
  - `PeakArbitrationRecord`
- 统一模块接口为 `contribute(runtime_state, candidates, memory_bank, context_chunks) -> ProbabilisticContribution`。
- 引入 `ProbabilityFieldIntegrator`，成为唯一融合入口，输出：
  - `context_attn_final`
  - `memory_prior_final`
  - `action_logits_final`
  - `token_logits_final`
  - `winner_posterior`
  - `counterfactual_top_peaks`
- 保留 v0.56 的 typed skill contract 思路，但 skill/output contract 改为可返回概率贡献载荷，而不是只返回 proposal/gate/state patch。

### 2. 主链重写为四层概率场
- 在 [`src/nalr/runtime/controller.py`](/Users/fantasylee/类脑架构/src/nalr/runtime/controller.py) 取消当前固定串行 `PIPELINE_ORDER` 作为决策真相，改为：
  - `State Encoding`
  - `Context Routing`
  - `Memory Reactivation`
  - `Action Proposal`
  - `Executive Reweighting`
  - `Conflict Arbitration`
  - `Guard Penalty`
  - `Token Sampling`
  - `Trace Commit`
- `Thalamus` 负责 context attention bias，不再只是末端 sampling。
- `Hippocampus` 负责模式分离、episode clustering、memory prior 注入，不再只是 recall text。
- `PFC + Identity + Authenticity + LongRun` 作为 executive layer，对 action/token 双层重打分。
- `ConflictMonitor` 改成峰值仲裁器，输出 `winner_peak_posterior`、suppression mask、compromise prior。
- `BehaviorPlausibilityGuard` 改成 soft penalty + hard block 双层守卫。
- `Renderer` 不再偷改决策内容，只消费最终概率场结果做表层表达。

### 3. 全模块同时概率化
- 所有在线模块都必须改成 first-class contribution producer：`Emotion`、`Body`、`Relationship`、`Resource`、`Habit`、`Desire`、`DMN`、`Perspective`、`Value` 不允许停留在旧 `ProposalBundle` 语义。
- `IdentityRuntime` 改成稳定 prior kernel；`AuthenticityPolicy` 改成在线失真惩罚项；`VitalityEngine` 改成全局调制器；`DreamOrchestrator` 改成离线生成式重放与先验再校准器。
- `SkillExecutor` 额外输出 `tool_affordance_prior`、`tool_cost_penalty`、`tool_expected_value`，使工具调用也进入 action/token 分布，而不是硬分叉。
- 推断性默认：
  - token-level 概率场通过 model gateway / decode bias / rerank 接口落地；
  - 真正的 transformer KV 注入只在 provider 支持时启用，否则以可观测的 bias 注入替代。
  - 这是基于当前代码只接远端模型路由的实现现实做的默认决定。

### 4. Trace / Observer / Diagnostics 全量换代
- 在 [`src/nalr/trace/store.py`](/Users/fantasylee/类脑架构/src/nalr/trace/store.py) 和 observer API 上重做 canonical schema，旧 `proposal_summaries/top_drivers/distribution_state` 不再作为主观察面。
- 新 trace 必须直接支持：
  - 每层贡献快照
  - 每模块 stacked contribution
  - token/action 被抬升或压制的原因
  - peak switch 轨迹
  - counterfactual replay
  - guard penalty 与 hard block 分离
- observer API、why/why-not、contribution heatmap、conflict diagnostics 全部切到新 schema。
- 旧 trace 只作为历史数据保留，不做读取兼容；提供一次性 rebuild/export 路径即可。

### 5. 执行组织与 superpower / agents 策略
- 执行必须走 `subagent-driven-development`，并在独立 worktree/branch 中完成。
- 采用 5 个并行 agent，写入范围严格分离：
  - Agent 1：runtime + schema + integrator
  - Agent 2：在线模块概率化改造
  - Agent 3：Identity / Authenticity / Vitality / Dream 先验系统
  - Agent 4：trace / observer / diagnostics
  - Agent 5：tests / migration scripts / verification
- 主代理负责：
  - 统一接口决策
  - 合并冲突
  - 阶段验收
  - 恢复 v0.56 工程护栏到终态
- 不再额外扩 agent 数量，避免写入面重叠。

## Test Plan

- 单元测试重写并新增：
  - 每个模块返回合法 `ProbabilisticContribution`
  - `ProbabilityFieldIntegrator` 在 context/memory/action/token 四层做正确融合
  - `ConflictMonitor` 可输出峰值仲裁与 compromise 路径
  - `Authenticity`、`Identity`、`Vitality`、`Dream` 都以 prior/penalty 形式进入最终分布
  - soft guard 与 hard block 行为分离
- 集成测试重写并新增：
  - `tick()` 产出四层概率快照与 token-level trace
  - token bias 能实际改变 decode 结果或 top-k 排序
  - observer/why/why-not/counterfactual 全部基于新 schema 正常返回
  - tool routing 进入 action 分布而非旁路
  - dream 更新先验后能在后续轮次改变 action/token 分布
- 回归验收：
  - 最终态恢复 typed contract 校验、fallback routing、breaker、safe mode、fault guard
  - 最终态保留显隐性边界：controller 编排、guard 不伪装动机、runtime 是唯一执行授权层
  - Parquet/JSON trace rebuild 能生成新 canonical 数据集
  - 旧 v0.56 pipeline tests 不保留原断言，统一改写为 v0.57 probability-field 断言

## Assumptions

- 5.7 是一次内部大版本式切换，不提供 v0.56 兼容读取层。
- 所有文档中列出的在线/离线模块都在同一改造线内完成概率化，不接受“适配层长期过渡”。
- 迁移中可以临时打破 v0.56 护栏，但最终合入态必须恢复这些工程原则。
- 当前远端模型能力限制下，token-level 改造默认以 decode/logit bias 可观测落地，不把“必须原生 KV 注入”设为首版阻塞条件。
