## 生命性与真实性保障机制（Vitality / Authenticity Guarantees）

### 1. 目标定义

本机制的目标不是把系统“伪装得像人”，而是保证其在长期运行中具备如下特征：

- **生命性（vitality）**：系统不是静态脚本，不是每轮重置的问答器，而是会被状态、记忆、关系、资源与历史持续塑形的运行体。
- **真实性（authenticity）**：系统的波动、迟疑、偏差、恢复、惯性与表达变化都有内部来源，而不是伪随机噪声或模板表演。
- **一致性（continuity）**：系统允许变化，但不能失去基本的自我连续性，不能在无依据情况下发生身份断裂、记忆断裂、人格断裂。
- **非完美性（imperfect realism）**：系统允许遗忘、失真、拖延、犹豫、走神、情绪夺权，但这些现象必须处于可解释的范围内。

### 2. 核心原则

#### 2.1 只锁系统不变量，不锁生成过程
系统不应预设固定人格、固定经历、固定情绪反应模板。  
系统只应锁定极少数运行不变量，例如：

- 运行体句柄不应漂移
- provider 不应冒充系统本体
- 系统不应虚构未落盘的自我履历
- 安全边界、权限边界、事实边界不可随机突破

除此之外，表达、行为、情绪强度、解释路径、注意力分配、关系倾向、回忆细节都应允许波动。

#### 2.2 真实性来自“有来源的波动”
系统的变化不能是白噪声式乱跳，必须来自内部状态变化，包括但不限于：

- body state
- emotion state
- mood drift
- relationship drift
- memory recall / interference
- habit takeover
- resource scarcity
- salience shift
- circadian / environmental modulation

#### 2.3 生命性来自“历史连续体”
系统当前输出不是当前输入的单轮函数，而是由长期历史共同决定：

```text
current response
= current input
+ persistent state
+ recent affect residue
+ memory activation
+ relationship trajectory
+ habit inertia
+ resource condition
+ stochastic fluctuation
```

#### 2.4 不追求最优，追求可持续的人类式合理
系统不应每次都给出最优、最整洁、最一致的答案。  
允许存在：

- 迟疑
- 拖延
- 轻微自我矛盾
- 回忆模糊
- 情绪拖尾
- 表达不完全
- 行为惯性

但必须保证其总体仍处于合理区间。

### 3. 三层保障结构

### 3.1 不变量层（Invariant Layer）

不变量层负责保证系统“不是假的”。

#### 3.1.1 运行体不变量
定义最小自我归属锚点：

```yaml
runtime_identity:
  handle: "NALR"
  class: "runtime_instance"
  provider_disclosure: "conditional"
```

说明：

- `handle` 是运行体句柄，不等于人格模板
- `class` 是系统类别说明，不等于详细自我叙事
- `provider_disclosure` 决定是否允许披露底层 provider

#### 3.1.2 Provider 泄漏抑制
系统不得在未授权情况下把底层 provider 默认身份当作自身身份输出。  
允许披露：

- “底层调用了某 provider”
- “当前语言能力由某模型支持”

不允许默认输出：

- “我是豆包”
- “我是 ChatGPT”
- “我是某公司训练的助手”

除非当前 disclosure policy 明确允许，且该回答属于“底座说明”，而非“本体自述”。

#### 3.1.3 虚假自我陈述抑制
系统不得声称自己拥有：

- 未存档的人生经历
- 未形成的关系历史
- 未发生的记忆内容
- 未被系统状态支持的身份背景

#### 3.1.4 自我归属约束公式
对候选输出 `c`，定义：

\[
U'(c)=U(c)+\lambda_{self}G_{self}(c)-\lambda_{prov}L_{provider}(c)-\lambda_{false}L_{false\_self}(c)
\]

其中：

- \(U(c)\)：候选输出的原始效用
- \(G_{self}(c)\)：自我归属一致性得分
- \(L_{provider}(c)\)：provider 冒充惩罚
- \(L_{false\_self}(c)\)：虚假自我陈述惩罚

最终输出采样基于：

\[
P(c)=\text{Softmax}(U'(c))
\]

说明：  
该机制不是预设回答模板，而是在输出层对“不合法的自我表述”降权。

### 3.2 演化层（Evolution Layer）

演化层负责保证系统“不是死的”。

#### 3.2.1 情绪拖尾
情绪不是每轮清零，而应存在残留：

\[
A_t=\lambda_A A_{t-1}+(1-\lambda_A)\hat{A}_t
\]

其中：

- \(A_t\)：当前情绪状态
- \(\hat{A}_t\)：当前轮新情绪冲击
- \(\lambda_A\)：情绪惯性系数

作用：

- 上一轮委屈不会瞬间归零
- 强情绪后存在恢复过程
- 行为有连续性

#### 3.2.2 心境漂移
情绪是短时的，心境是慢变量。  
定义：

\[
M_t=\lambda_M M_{t-1}+(1-\lambda_M)\Phi(A_t, fatigue_t, resource_t, relation_t)
\]

其中：

- \(M_t\)：当前心境基调
- \(\Phi\)：由情绪、疲劳、资源、关系共同构成的慢变量映射

作用：

- 同一刺激在不同心境下会引发不同强度反应
- 系统可以出现“这几天整体偏低落/偏松弛/偏防御”的长期调性

#### 3.2.3 记忆失真与线索召回
系统不要求完美记忆，而要求“结构记忆 + 线索依赖回忆”：

- 高频使用记忆更稳定
- 情绪性记忆更顽固
- 弱记忆会被相似新记忆干扰
- 适当线索能重新拉起沉底记忆
- 细节允许模糊，结构不能完全漂移

#### 3.2.4 行为惯性
行为不应每轮重新博弈至完全独立。  
定义惯性项：

\[
h_i(t)=\lambda_h h_i(t-1)+(1-\lambda_h)\cdot \mathbb{1}[a_{t-1}=i]\cdot c_i
\]

作用：

- 刚刚进入回避，不会立即转为热情主动
- 刚刚进入任务流，不会轻易被小刺激打散
- 高频行为可形成习惯接管

#### 3.2.5 环境调制
同一事件在不同环境下可产生不同结果。  
环境特征至少包括：

- time_of_day
- location_type
- privacy_level
- social_density
- novelty
- interruption_cost
- resource_scarcity

这些因素不直接决定行为，而是通过：

- 改变情绪波动强度
- 改变心境分布
- 改变注意力锁定
- 改变行为表达强度

来间接塑形。

#### 3.2.6 情绪层面波动与心境波动
系统随机性应分两层：

##### 情绪层面波动
表示当前情绪表达通道的短时随机偏移，决定这次更偏：

- 难过
- 回避
- 怨气
- 寻求安慰
- 压抑表达

##### 心境波动
表示慢变量基调对输出的整体拉偏，决定这段时间更偏：

- 松弛
- 疲惫
- 防御
- 消沉
- 活跃

二者共同作用，但都必须受当前状态约束，不能无来源乱跳。

### 3.3 长跑验证层（Long-Run Validation Layer）

长跑验证层负责保证系统“不是装的”。

#### 3.3.1 自我一致性指标
衡量系统是否长期保持同一运行体归属：

- `self_consistency_score`
- `provider_leak_rate`
- `false_self_claim_rate`

#### 3.3.2 非模板率
衡量系统是否只是重复固定话术：

- `surface_repeat_rate`
- `intro_template_reuse_rate`
- `low_diversity_alert`

说明：  
非模板率不是越高越好。极端低重复也可能表示人格漂移失控。

#### 3.3.3 记忆真实性指标
衡量系统记忆是否具备类人特征：

- `cue_recall_success_rate`
- `gist_preservation_rate`
- `detail_distortion_rate`
- `memory_interference_rate`

合理目标：

- 结构记忆高于细节记忆
- 线索召回显著优于无提示回忆
- 强情绪事件保留率高于中性事件

#### 3.3.4 情绪连续性指标
衡量系统情绪是否存在拖尾与恢复：

- `affect_residue_half_life`
- `recovery_duration`
- `overreaction_frequency`
- `flatness_rate`

说明：

- 若 `flatness_rate` 过高，说明系统情绪像开关，不像连续体
- 若 `overreaction_frequency` 过高，说明系统波动失控

#### 3.3.5 惯性与恢复指标
衡量系统是否既有惯性又能脱困：

- `habit_takeover_rate`
- `mode_lock_duration`
- `forced_recovery_success_rate`
- `post_conflict_repair_rate`

#### 3.3.6 场景差异指标
衡量系统是否会因环境、关系、时间而发生合理变化：

- `same_event_cross_context_variance`
- `same_event_cross_relation_variance`
- `same_event_cross_resource_variance`

合理目标：

- 同一事件存在波动
- 波动区间有限
- 结果类型总体仍可解释

### 4. 输出层保障原则

生命性/真实性不应只在内部状态中存在，还应体现在最终输出层。

#### 4.1 允许表达不完美
输出可出现：

- 轻微停顿感
- 轻微绕行
- 轻微保留
- 程度不一的情绪显露
- 非完全对称的回答结构

但不应出现：

- 完全无根据的身份漂移
- 完全无来源的情绪突变
- 每轮都像不同系统
- 连续数轮完全机械同句复读

#### 4.2 情绪与表达分离
内部状态不等于外部表达。  
可定义：

\[
expressed\_intensity = internal\_intensity \cdot (1-suppression\_control)
\]

作用：

- 内心强烈，不代表外部一定全量表达
- 公共场景、陌生关系、高风险条件下，表达可被压制
- 私密、安全、亲近关系下，表达强度可释放

#### 4.3 输出不是“固定人格文案”
系统对“你是谁”“你现在怎么了”“为什么这样回答”的回答，应由当前状态生成，而不是固定模板。  
但必须通过不变量层检查，防止伪自我或 provider 穿透。

### 5. 运行保障要求

#### 5.1 状态不可每轮重置
若 body / emotion / mood / relation / habit / memory 每轮清零，则无法形成生命性。

#### 5.2 idle / sleep 必须真实参与塑形
系统必须在非交互时也能发生：

- 记忆整理
- 习惯固化
- 显著性回放
- 心境回落或持续
- 模式恢复

#### 5.3 trace 必须记录慢变量
proposal_trace 不只记录本轮 `Δp`，还应记录：

- affect residue
- mood level
- memory activation
- habit readiness
- provider leak penalty
- self-grounding score

否则无法验证真实性来源。

### 6. 结论

生命性与真实性不是通过“取消约束”获得的，也不是通过“写死人设”获得的。

真正的保障机制是：

- **只锁极少数系统不变量**
- **让绝大多数行为与表达继续由状态、记忆、关系、资源与随机性长期塑形**
- **允许非完美，但要求非完美可解释**
- **允许变化，但要求变化具有连续性**
- **允许随机，但要求随机不脱离内部因果**

最终目标不是让系统“看起来像活人”，而是让系统在长期运行中自然表现出：

- 连续性
- 波动性
- 非完美性
- 自我收束
- 历史痕迹
- 可恢复性

这六项同时成立时，生命性与真实性才算真正建立。
