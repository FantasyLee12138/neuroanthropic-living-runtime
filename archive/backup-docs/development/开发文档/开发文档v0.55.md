# 类脑活人架构 v0.55
## Engineering Spec / CLI / Always-on / Multi-Agent / Probability-Driven Runtime

> 本版本为 **v0.4 的工程化修订版**。  
> 若 v0.55 与 v0.5 / v0.4 冲突，以 **v0.55** 为准。  
> 本版本不再追求“概念尽可能全”，而追求“可实现、可调参、可降级、可验证”。

---

## 0. v0.55 修订摘要

v0.55 在 v0.5 的基础上，继续补齐“情境随机性”的工程规格。重点覆盖七类问题：

1. **参数空白** → 补齐默认参数、阈值、上限、场景预设
2. **资源映射抽象** → 给出资源量化、模式阈值、行为偏移映射
3. **冲突闭环不完整** → 引入冲突优先级、最大重采样次数、妥协策略
4. **长期稳定性不足** → 增加存储压缩、缓存上限、过载保护、降级梯度
5. **调试链路不完整** → 明确 trace 存储格式、可视化路径、模块开关与贡献分析
6. **“活人感”不可验证** → 引入场景预设、表达层、量化评估指标
7. **随机性落地不完整** → 引入情境随机层、情绪层面波动、心境波动与强度采样

v0.55 的目标是：

- 让架构 **先能稳定跑起来**
- 让参数 **先能被控制和复现**
- 让异常 **先能被定位和回退**
- 让“拟人感” **先能被测量，而不是只靠主观印象**

## 1. 版本定位

v0.55 不是一份“最终认知科学理论”，而是一份 **可调试的工程规格书**。

### 1.1 核心原则

1. **先离散化，再精细化**  
   先把心理机制压成有限状态、有限参数、有限边界，再逐步拟合真实人类复杂性。

2. **先可跑，再可爱**  
   不允许“活人感”建立在系统不稳、难调、难复现的基础上。

3. **先限权，再开放**  
   任何 Agent 都不能无限放大自身影响；所有偏移必须可裁剪、可降级、可审计。

4. **先场景化，再通用化**  
   对话、陪伴、任务执行是不同 runtime；不再默认同一套权重通吃。

## 3. 工程边界与性能约束

### 3.1 运行目标

| 模式 | 目标 | 延迟预算 |
|---|---|---:|
| interactive | 单轮对话、即时反馈 | p95 首 token ≤ 700ms；p95 全轮 ≤ 1800ms |
| auto-run | 持续自主运行 | 单轮认知调度 ≤ 1200ms；平均 CPU/Token burn 受配额控制 |
| idle | 背景整理、轻联想 | 每 tick ≤ 300ms；默认 5s~60s 动态周期 |
| sleep | 重放、压缩、遗忘 | 离线批处理，允许秒级 |

### 3.2 单轮预算拆分（interactive 缺省）

| 模块 | 预算上限 |
|---|---:|
| 状态更新 + 规则 Agent | 120ms |
| 记忆检索 | 180ms |
| PFC 候选生成 | 350ms |
| Value / Conflict / Thalamus | 160ms |
| 最终语言输出前校准 | 100ms |
| 日志写入（异步） | 60ms |

### 3.3 技术选型边界

v0.5 不建议一上来引入 Drools 这类重量规则引擎。首版推荐：

- **规则层**：typed YAML / JSON policy tables + Python/TypeScript evaluator
- **状态机**：显式状态图 + 数值阈值
- **检索层**：embedding + ANN + reranker
- **小模型层**：3B~8B 指令模型，仅在需要语义泛化的模块启用
- **主模型层**：只给 PFCAgent、最终语言输出、高风险社交推断

## 5. 行为采样总公式（v0.5）

### 5.1 最终行为概率

```text
P_raw(a_i) =
    P_base(a_i)
  + Σ_j [ w_j × Δp_j(a_i) × conf_j ]
  + Δp_context(a_i)

P_final(a_i) = Normalize( Clip(P_raw(a_i), p_floor, p_cap) ) × Gate(a_i)
```

缺省值：

- `p_floor = 0.01`
- `p_cap = 0.85`
- `w_j ∈ [0.2, 1.4]`
- `conf_j ∈ [0, 1]`

### 5.2 置信区间更新

v0.4 的“按场景切换 α/β”过于粗糙。  
v0.5 改为统一更新，再裁剪：

```text
CI_{t+1}(a_i)
= clip(
    CI_t(a_i)
    × narrow_factor(a_i)
    × widen_factor(a_i)
    × overload_guard(a_i),
    CI_min,
    CI_max
  )
```

缺省值：

- `CI_min = 0.08`
- `CI_max = 0.55`

其中：

```text
narrow_factor = 1 - k_if × IF - k_neg × NEG - k_habit × HAB
widen_factor  = 1 + k_idle × IL + k_uncertainty × UNC
overload_guard = 1 + k_overload × OV
```

默认系数：

- `k_if = 0.18`
- `k_neg = 0.22`
- `k_habit = 0.15`
- `k_idle = 0.25`
- `k_uncertainty = 0.10`
- `k_overload = 0.08`

并执行裁剪：

```text
narrow_factor ∈ [0.55, 1.0]
widen_factor ∈ [1.0, 1.45]
overload_guard ∈ [1.0, 1.15]
```

### 5.3 用户给出的 IF / ET / IL 公式的 v0.5 修订版

#### 交互频率 IF

```text
IF = min(1, ( Σ_i exp(-λ·Δt_i) ) / IF_norm )
```

默认：

- `λ = ln(2) / H`
- `H = 3 days`（半衰期）
- `IF_norm = 8`

说明：  
v0.4 用固定窗口 + τ 的表达可行，但工程上更适合用 **半衰期衰减**，便于统一跨 round / 分钟 / 天。

#### 负向体验强度 NEG

```text
NEG = clip(max(0, -S_e), 0, 1)
POS = clip(max(0,  S_e), 0, 1)
```

其中 `S_e ∈ [-1, 1]`。

v0.5 不再直接把体验映射成 `ET ∈ [0.95, 2.0]` 后再乘到 α，原因是：
- 正负项混在一个系数里，调参不直观
- 会放大极端样本
- 不利于线上诊断

改为正负分离，更利于解释。

#### 空闲程度 IL

```text
IL = clip( idle_ratio × (1 - task_load) × (1 - alertness_override), 0, 1 )
```

默认：

- `idle_ratio = min(1, T_idle / T_max_idle)`
- `T_max_idle = 30 min`
- `alertness_override = 1` 当 `salience >= 0.78`，否则 `0`

说明：  
避免“系统明明空闲，但高显著性事件发生时仍错误放宽”的问题。

### 5.4 情境随机层（Contextual Stochasticity Layer）

原则：  
**随机性不直接乘在最终归一化后的概率上**。  
v0.55 采用“确定性倾向 + 情境随机扰动 + 强度采样”的三段式结构：

1. **确定性倾向** 决定大方向
2. **情绪层面波动** 决定本轮更偏哪种情绪表达通道
3. **心境波动** 决定同一情绪通道内的细微差异
4. **强度采样** 决定本轮表现“有多强”

这样可以满足：

- 同一事件不会每次都触发完全相同的动作
- 但输出仍落在合理情绪范围内
- “生气 / 难过”可保持同类倾向，只在程度与细节上波动
- 可复现、可 debug、可裁剪

### 5.5 动作倾向的确定性底座

对每个候选动作 \(a_i\)，先计算未归一化的倾向分数：

```text
u_i(t)
= b_i
+ Σ_agent Δu_agent,i(t)
+ Σ_k w_env,k,i · E_k(t)
+ h_i(t)
```

其中：

- `b_i`：动作基线
- `Δu_agent,i`：各 Agent 对动作 `i` 的贡献，建议直接由 `delta_p` 线性映射到 logit 空间
- `E_k(t)`：环境特征
- `h_i(t)`：惯性 / 滞后项

推荐环境特征最少包含：

- `time_of_day`
- `location_type`
- `privacy_level`
- `noise_level`
- `social_density`
- `novelty`
- `resource_scarcity`
- `circadian_offset`

惯性项采用一阶平滑：

```text
h_i(t)
= λ_h · h_i(t-1)
+ (1 - λ_h) · 1[a_{t-1}=i] · c_i
```

默认：

- `λ_h = 0.72`
- `c_i ∈ [0.02, 0.12]`

解释：  
人类不是每轮都“重新洗牌”；上一轮已经回避、拖延、委屈或强撑，这一轮更容易沿原轨迹延续。

### 5.6 情绪层面波动与心境波动

v0.55 不再使用“家族级波动 / 动作微波动”的命名。  
统一改为：

- **情绪层面波动（emotion-level fluctuation）**
- **心境波动（mood fluctuation）**

#### 5.6.1 情绪层面波动

每个候选动作先映射到一个主情绪通道 `emo(i)`，例如：

- `sadness`
- `anger`
- `fear`
- `withdrawal`
- `comfort_seek`
- `task_hold`

同一情绪通道共享一个随机项：

```text
ξ_emo(g, t) ~ TruncNormal(0, σ_emo^2(t), -2σ_emo, +2σ_emo)
```

其中 `g = emo(i)`。

含义：  
同一轮里，如果系统整体更偏“受伤 / 低落”或更偏“烦躁 / 防御”，这种偏移应同时影响同通道动作，而不是彼此独立乱跳。

#### 5.6.2 心境波动

在同一情绪通道内部，每个动作还拥有一个更小的局部波动：

```text
ξ_mood(i, t) ~ TruncNormal(0, σ_mood^2(t), -σ_mood, +σ_mood)
```

默认：

```text
σ_mood(t) = 0.5 · σ_emo(t)
```

含义：  
同样是难过，这次可能更偏“沉默”，下次可能更偏“解释几句后沉下去”；  
但不会从“难过”直接随机翻成“兴奋”或“攻击”。

### 5.7 随机项的乘性注入方式

定义乘性扰动：

```text
m_i(t) = exp( ρ_emo · ξ_emo(emo(i), t) + ρ_mood · ξ_mood(i, t) )
```

再把它注入未归一化分数：

```text
ũ_i(t) = u_i(t) + log(m_i(t))
```

等价于：

```text
exp(ũ_i) = exp(u_i) · m_i
```

说明：  
这就是“随机乘一个系数”的工程化写法，但**乘在未归一化分数上，而不是最终概率上**。  
这样做的好处是：

- 不会破坏概率分布的数学合法性
- 可以继续自然地做 softmax / normalize
- 更容易对强动作、弱动作和门禁动作做统一裁剪

默认：

- `ρ_emo = 1.00`
- `ρ_mood = 0.60`

### 5.8 情境波动度：决定随机幅度，而不是固定乱抖

随机性幅度不设固定值，而由当前情境波动度 `V_t` 决定：

```text
V_t
= clip(
    0.25 · novelty
  + 0.20 · emotion_volatility
  + 0.15 · fatigue
  + 0.10 · privacy_shift
  + 0.10 · location_shift
  + 0.10 · circadian_offset
  + 0.10 · resource_scarcity
  - 0.10 · salience_lock
  - 0.10 · habit_strength
  , 0, 1
)
```

然后：

```text
σ_emo(t) = σ_emo_min + (σ_emo_max - σ_emo_min) · V_t
σ_mood(t) = σ_mood_min + (σ_mood_max - σ_mood_min) · V_t
```

默认：

- `σ_emo_min = 0.03`
- `σ_emo_max = 0.18`
- `σ_mood_min = 0.015`
- `σ_mood_max = 0.09`

解释：  
越陌生、越疲惫、越波动、越缺资源，随机幅度越大；  
越高显著锁定、越习惯化，随机幅度越小。

### 5.9 基准分布、随机分布与最终混合

先计算无随机基准分布：

```text
P_base_stochastic(a_i) = Softmax(u_i(t))
```

再计算带随机扰动的候选分布：

```text
Q_noise(a_i) = Softmax(ũ_i(t))
```

最终分布采用可调混合：

```text
P_mix(a_i)
= Normalize(
    (1 - λ_noise(t)) · P_base_stochastic(a_i)
  + λ_noise(t) · Q_noise(a_i)
)
```

其中：

```text
λ_noise(t)
= clip(
    λ0
  + 0.25 · V_t
  - 0.12 · control_strength
  + debug_noise_override,
    0,
    λ_runtime_cap
)
```

默认建议：

- `λ0 = 0.10`
- `λ_runtime_cap = 0.60`
- `debug_noise_override = 0`（debug 时可临时放宽）

说明：  
v0.55 **不再设置固定的全局“随机最多只接管 35%”硬约束**。  
随机混合权重改为运行时参数，由场景、控制强度、调试模式共同决定；正式运行建议保守，debug 可放开。

随后再并回主采样流程：

```text
P_final(a_i)
= Normalize( Clip( P_mix(a_i), p_floor, p_cap ) ) × Gate(a_i)
```

### 5.10 强度采样：保证“结果同类，但程度不同”

同一事件下，人类往往不是动作类别变化，而是**表达强度**不同。  
因此 v0.55 要求把“类别采样”和“强度采样”分开。

先估计强度均值：

```text
μ_int(t)
= clip(
    sigmoid(
        γ0
      + γ1 · affect_load
      + γ2 · arousal
      + γ3 · privacy_level
      - γ4 · self_control
      - γ5 · relationship_risk
    ),
    0.05, 0.95
)
```

再定义集中度：

```text
κ_t = clip(16 - 10 · V_t, 4, 16)
```

最终采样：

```text
r_intensity(t) ~ Beta( μ_int(t)·κ_t , (1-μ_int(t))·κ_t )
```

默认：

- `γ0 = -0.20`
- `γ1 = 1.10`
- `γ2 = 0.55`
- `γ3 = 0.35`
- `γ4 = 0.80`
- `γ5 = 0.60`

解释：  
- 高负面负荷、高唤醒、私密场景 → 强度更高
- 高自控、高关系风险 → 强度更低
- 情境越不稳定，强度分布越分散

### 5.11 强度到输出层的映射

采样到的 `r_intensity ∈ [0,1]` 必须写入 OutputStyleLayer，而不是只停在内部状态：

```text
reply_delay
= d_min + r_intensity · (d_max - d_min)

self_disclosure
= s_min + r_intensity · (s_max - s_min)

tone_sharpness
= t_min + r_intensity · (t_max - t_min)

repair_tendency
= r_min + (1 - r_intensity) · (r_max - r_min)
```

含义：

- 同样是受伤，这次可能只是“轻微低落 + 回复慢一点”
- 下次可能是“明显难过 + 更少解释 + 更想独处”
- 但不会跳出合理情绪通道

### 5.12 调试与安全边界

情境随机层必须额外记录：

- `round_seed`
- `emo_channel`
- `ξ_emo`
- `ξ_mood`
- `λ_noise`
- `r_intensity`
- `KL(Q_noise || P_base_stochastic)`

推荐保护：

```text
|log(m_i)| <= 0.35
KL(Q_noise || P_base_stochastic) <= 0.15
```

若超界，则按顺序执行：

1. 回拉 `λ_noise`
2. 回拉 `σ_emo / σ_mood`
3. 回退到 `P_base_stochastic`
4. 保留 trace 并标记 `noise_guard_triggered = true`

另外：

- `Gate(a_i) = 0` 的动作不得被随机性复活
- 高风险动作默认乘以额外抑制项 `risk_suppressor ∈ [0.4, 1.0]`
- 陌生关系 / 公共场景下，`ρ_emo` 与 `ρ_mood` 默认下降 10%~25%

## 6. ResourceAgent：从抽象隐喻改成量化预算层

### 6.1 统一资源指标

```text
scarcity_index
= clip(
    0.40 * burn_rate_ratio
  + 0.30 * low_balance_ratio
  + 0.20 * queue_pressure
  + 0.10 * latency_pressure,
    0, 1
  )
```

其中：

- `burn_rate_ratio = current_burn / target_burn`
- `low_balance_ratio = 1 - remaining_budget_ratio`
- `queue_pressure = queue_len / queue_cap`
- `latency_pressure = p95_latency / latency_sla`

### 6.2 资源模式阈值

| 模式 | scarcity_index |
|---|---:|
| abundant | [0.00, 0.25) |
| stable | [0.25, 0.50) |
| scarce | [0.50, 0.75) |
| starvation | [0.75, 1.00] |

### 6.3 行为偏移映射

```text
body_hunger_bias       = 0.10 + 0.55 * scarcity_index
effort_avoidance_bias  = 0.05 + 0.45 * scarcity_index
deliberation_compress  = 1.00 - 0.50 * scarcity_index
rumination_bias        = 0.05 + 0.35 * scarcity_index
action_shrink_scale    = 1.00 - 0.40 * scarcity_index
```

### 6.4 映射到具体动作概率

对常见动作类别定义统一偏移：

```text
Δp(delay_reply)      += +0.18 * body_hunger_bias
Δp(short_reply)      += +0.15 * deliberation_compress
Δp(explore_new_path) += -0.20 * action_shrink_scale
Δp(reuse_habit)      += +0.22 * effort_avoidance_bias
Δp(deep_plan)        += -0.25 * effort_avoidance_bias
```

说明：  
这解决了 v0.4 中“饥饿偏置 0.3 究竟意味着什么”的问题。  
在 v0.5 中，任何资源隐喻都必须落到 **动作偏移表** 或 **模块资源占比表** 上。

### 6.5 starvation 模式的硬约束

当 `scarcity_index >= 0.75`：

- 禁止非必要 PerspectiveModel
- 禁止长链 PFC 深规划
- 禁止二次以上重采样
- 输出长度上限降到默认的 40%
- 仅保留：
  - Body/Resource/Thalamus
  - Habit
  - 必要的 Relationship 安全约束
  - 最小 PFC 候选生成

## 7. 动态资源分配：从固定倍率改成“带下限的连续调度”

### 7.1 统一公式

```text
share(agent) =
clip(
    base_share(agent)
  * mode_modifier(agent)
  * salience_modifier(agent)
  * scarcity_modifier(agent)
  * execution_need_modifier(agent),
    share_min(agent),
    share_max(agent)
)
```

### 7.2 关键模块资源占比上下限

| 模块 | share_min | share_max |
|---|---:|---:|
| PFC | 0.12 | 0.40 |
| Hippocampus | 0.08 | 0.28 |
| Habit | 0.08 | 0.24 |
| Relationship | 0.08 | 0.24 |
| Body / Resource | 0.10 | 0.22 |
| DMN | 0.03 | 0.15 |
| Conflict / Guard | 0.06 | 0.18 |
| Thalamus | 0.08 | 0.20 |

### 7.3 高显著性事件修订

v0.4 的 “×2.0” 改为：

```text
salience_modifier = 1 + 0.8 * clamp((salience - 0.78) / 0.22, 0, 1)
```

这样：

- `salience = 0.78` → 1.00
- `salience = 0.90` → 1.44
- `salience = 1.00` → 1.80

原因：
- 避免固定翻倍在高负载场景造成新的过载
- 能与系统当前压力连续耦合

### 7.4 idle 模式保障阈值

idle 时不再允许 PFC 掉到 10% 以下。  
缺省：

- `PFC share_min = 0.12`
- `Thalamus share_min = 0.08`
- `Conflict/Guard share_min = 0.06`

这用于防止“发呆模式把核心执行能力直接饿死”。

### 7.5 过载保护耦合

若 `queue_pressure > 0.85` 或 `latency_pressure > 1.20`：

- 暂停放大 `salience_modifier`
- `execution_need_modifier` 对非关键模块强制下压到 `0.7`
- 取消非必要 DMN / Perspective 唤醒
- 将 `max_resample_rounds` 从 2 降到 1

## 8. 冲突闭环：优先级、重采样、妥协规则

### 8.1 冲突分数

```text
conflict_score =
  0.35 * proposal_divergence
+ 0.20 * veto_tension
+ 0.20 * value_gap
+ 0.15 * relation_risk_gap
+ 0.10 * body_state_gap
```

### 8.2 冲突优先级

出现冲突时，按以下顺序裁决：

1. **生理 / 安全约束**
2. **系统预算 / 过载约束**
3. **关系安全 / 边界约束**
4. **任务目标**
5. **即时欲望**
6. **好奇 / 探索 / DMN 漫游**

### 8.3 重采样规则

- `conflict_score < 0.65`：不重采样
- `0.65 <= conflict_score < 0.82`：允许 1 次重采样
- `>= 0.82`：最多 2 次重采样，且必须启用妥协模板

### 8.4 多轮冲突后的妥协模板

若达到 `max_resample_rounds` 仍冲突，禁止继续死循环，强制落到以下模板之一：

1. **生理优先妥协**：缩短输出、延迟动作、减少承诺
2. **关系优先妥协**：保留礼貌边界，降低自我暴露
3. **任务优先妥协**：给最小可执行下一步，不做展开
4. **预算优先妥协**：走习惯路径或模板路径

### 8.5 冲突死锁熔断

若连续 `3` 轮进入 `critical conflict`：

- 输出 `hesitation / uncertainty` 风格
- 禁止 high-risk action
- 强制提升 PFC + Conflict 权重 1 轮
- 给 Runtime 打 `conflict_hot` 标记，持续 5 轮

## 9. HabitAgent：补足量化、上限与恢复规则

### 9.1 习惯强度公式

```text
habit_strength_t =
clip(
    (1 - decay_h) * habit_strength_{t-1}
  + η_pos * positive_feedback
  - η_neg * negative_feedback
  + η_rep * repeat_signal
  + η_ctx * context_similarity,
    0, 1
)
```

默认：

- `decay_h = 0.015 / tick`
- `η_pos = 0.06`
- `η_neg = 0.08`
- `η_rep = 0.04`
- `η_ctx = 0.03`

### 9.2 反馈时效系数

```text
feedback_weight(Δr) = exp(-ln(2) * Δr / H_fb)
```

默认：

- `H_fb = 6 rounds`

所以：

- 即时反馈 ≈ 1.0
- 6 轮后 ≈ 0.5
- 10 轮后 ≈ 0.32

### 9.3 默认动作建议阈值

| habit_strength | 含义 |
|---|---|
| < 0.35 | 不足以接管 |
| 0.35~0.60 | 只提供候选偏移 |
| 0.60~0.80 | 低冲突场景可默认接管 |
| > 0.80 | 高稳定默认路径，但仍受 Guard 裁剪 |

### 9.4 反向习惯突破奖励上限

v0.4 的“额外提升 Δp”没有上限。  
v0.5 改为：

```text
breakthrough_bonus = min(0.08, 0.04 + 0.06 * success_signal)
```

并且：

- 同一上下文 10 轮内最多触发 2 次
- 不允许单次将新行为概率抬升超过 `+0.10`
- 旧习惯不会瞬间清零，而是进入 `suppressed but recoverable` 状态

### 9.5 旧习惯受干扰后的恢复

若旧习惯被新行为压制：

```text
recovery_rate = 0.02 + 0.03 * context_recurrence
```

说明：  
这保证“人类习惯改变是渐进的”，而不是一次正反馈就彻底改头换面。

## 10. HippocampusAgent：补足阈值、恢复与压缩策略

### 10.1 记忆强度

```text
memory_strength_t =
clip(
    memory_strength_{t-1}
    * (1 - decay_rate)
    + cue_boost
    + affect_boost
    - interference_penalty,
    0, 1
)
```

### 10.2 基础衰减率（按模式）

| 模式 | base_decay / tick |
|---|---:|
| interactive | 0.010 |
| task | 0.008 |
| idle | 0.016 |
| sleep compression | 0.020 |

### 10.3 线索与情绪修正

```text
cue_decay_modifier =
  0.70 if recalled_within_window
  else 1.00

affect_decay_modifier =
  0.55 if affect_intensity >= 0.75
  0.85 if 0.40 <= affect_intensity < 0.75
  1.20 if affect_intensity < 0.20
```

### 10.4 相似记忆干扰

```text
interference_penalty =
  0.18 * sim(new, old) * (1 - old_strength)
```

只在以下条件同时满足时触发：

- `sim(new, old) >= 0.82`
- `old_strength <= 0.45`
- 两条记忆属于同类 context slot

### 10.5 弱记忆恢复规则

当弱记忆被干扰后，若后续触发高质量线索：

```text
cue_boost = 0.12 + 0.20 * cue_quality
```

其中 `cue_quality ∈ [0,1]`。  
高质量线索示例：

- 明确时间 + 人物 + 情绪
- 原句引用
- 与 RawEvidenceStore 指针直接对齐

### 10.6 gist fallback 阈值

- `memory_strength >= 0.50`：可回放较稳定 detail
- `0.25 <= strength < 0.50`：优先 gist
- `< 0.25`：只允许低置信召回或不召回

### 10.7 存储清理 / 压缩

- 最近 `500 rounds`：hot episodic，保留细节
- `501~3000 rounds`：warm episodic，保留 gist + 证据指针
- `>3000 rounds`：归档为 schema / summary chunk
- RawEvidence 缺省保留：
  - 热数据 7 天
  - 温数据 30 天
  - 长期只保留被引用证据和哈希摘要

## 11. Temperament：从示意公式改成受约束的慢变量系统

### 11.1 参数边界

所有 temperament 变量必须满足：

```text
temperament_k ∈ [0,1]
drift_k ∈ [-0.25, +0.25]
current_k = clip(baseline_k + drift_k, 0, 1)
```

### 11.2 交互项示例（可执行版）

#### 依恋 × 边界

```text
approach_pull   = attachment_need
approach_brake  = 1 - boundary_softness
approach_tension = clip(approach_pull * approach_brake, 0, 1)
```

输出解释：

- 高 `approach_tension`：更可能出现“想接近但先试探、绕弯、延迟确认”

#### 敏感 × 耐心

```text
reactive_fragility = clip(sensitivity * (1 - patience), 0, 1)
```

影响：

- 负向事件的 `NEG` 放大因子
- hesitation 概率上升

#### 外向 × 认知带宽

```text
social_output_capacity = clip(extraversion * cognitive_bandwidth, 0, 1)
```

影响：

- 主动表达概率
- 语句组织稳定性
- “话多但乱”的触发概率

### 11.3 压力漂移与回归

```text
drift_k(t+1) =
clip(
    drift_k(t) * (1 - recover_rate_k)
  + stress_push_k
  + experience_push_k
  + relation_push_k,
    -0.25, +0.25
)
```

默认恢复率：

| 参数 | recover_rate |
|---|---:|
| patience | 0.03 |
| sensitivity | 0.02 |
| boundary_softness | 0.025 |
| desire_priority | 0.02 |

### 11.4 异常值校准

当外部配置或模块计算导致 temperament 越界：

1. 先 clip 到 `[0,1]`
2. 记录一次 `temperament_correction_event`
3. 若同一参数 20 轮内越界超过 3 次，冻结该参数的外部写入 10 轮

## 12. Behavior Plausibility Guard：把“像人”变成显式校验层

### 12.1 合理性失败分数

```text
plausibility_fail_score =
  0.30 * disclosure_risk
+ 0.25 * relation_mismatch
+ 0.20 * body_mismatch
+ 0.15 * task_value_mismatch
+ 0.10 * style_mismatch
```

### 12.2 典型触发条件

- 陌生关系下高自我披露

- 极低预算下高展开、高承诺

- `0.50~0.70`：软警告，降低相关动作概率 15%
- `0.70~0.85`：强制二次采样
- `>0.85`：直接 veto 高风险候选，回退到保守模板

## 13. 故障兜底：从“崩了就替换 baseline”改成降级梯度

### 13.1 Agent 响应梯度

| 状态 | 判定 | 处理 |
|---|---|---|
| healthy | 正常响应 | 正常参与 |
| slow | 超时但有响应 | 降权到 0.6，保留上轮输出平滑 |
| degraded | 连续 2 轮超时 / 异常 | 降权到 0.3，仅允许 neutral delta |
| failed | 连续 3 轮失败 | baseline 代替，并记录故障 |
| quarantined | 高频异常 | 暂停 20 轮，仅健康检查 |

### 13.2 Light Cache Mode 细化

当记忆层读写失败时，切到轻量缓存模式：

- `session_cache_cap = 256 items`
- `ttl = 2 hours`
- FIFO + LRU 混合淘汰
- 只缓存：
  - 最近互动摘要
  - 关系关键 delta
  - 当前 habit 命中
  - 未落盘 trace 索引

### 13.3 概率异常保护

出现以下任意情况即触发回退：

- NaN / inf
- 归一化后概率和偏离 `1 ± 0.01`
- 超过 `3` 个动作同时到 `p_cap`
- `sigma_scale <= 0`

处理顺序：

1. clip
2. rollback 上一轮有效参数
3. 退回 baseline 分布
4. 若连续 3 轮仍异常，进入 `safe mode`

### 13.4 Safe Mode

safe mode 下仅保留：

- Body / Resource
- Relationship 安全边界
- 最小 PFC
- Thalamus
- OutputGate

并禁止：

- DMN
- Perspective
- 二次重采样
- 长回复

## 14. 长期运行：防膨胀、防抖动、防过载

### 14.1 存储膨胀控制

| 层 | 热存上限 | 处理方式 |
|---|---:|---|
| WorkingMemory | 3 propositions | 覆盖写 |
| Episodic hot | 500 | 超出即压缩 |
| HabitMemory | 200 active patterns | 低频链路降级为 dormant |
| RelationshipMemory | 128 entities | 长尾对象冷冻 |
| SchemaMemory | 256 chunks | 合并重复 schema |
| RawEvidenceStore | 2GB 或 30 天 | 过期归档/哈希化 |

### 14.2 Habit 高频缓存

对最近 20 个高频 context 开启命中缓存：

- TTL = 30 min
- 命中后直接跳过完整检索
- 但遇到：
  - 高显著性
  - 高冲突
  - 关系变动
  - 安全标记
  时强制失效

### 14.3 过载保护

引入事件保险丝：

```text
event_fuse_triggered if
  input_rate > rate_cap
  or queue_len > queue_cap
  or cpu_pressure > 0.90
```

缺省：

- `rate_cap = 12 events / 10 sec`
- `queue_cap = 64`
- `cpu_pressure = host specific normalized metric`

触发后：

- 丢弃低优先级 idle 事件
- 冻结 DMN
- 简化输出
- 合并重复输入
- 对恶意 prompt / 高频 CLI 做节流

## 20. 评估体系：把“活人感”拆成能打分的指标

### 20.1 评估维度

| 维度 | 指标 | 目标 |
|---|---|---|
| 稳定性 | 崩溃率 / safe mode 触发率 | 越低越好 |

| 习惯渐进性 | 新习惯达到 0.7 强度所需中位轮数 | 8~30 轮 |
| 记忆拟人性 | gist recall/detail recall 比 | 先 gist 后 detail |
| 表达拟人性 | 节奏方差 / 句长方差 / 修正率 | 不为零但受控 |
| 关系一致性 | 关系状态与表达风格匹配率 | > 85% |
| 任务可靠性 | task 模式下执行成功率 | > 90% |
| 可解释性 | why-this 能还原主要驱动 | Top-3 驱动覆盖率 > 80% |

### 20.2 关键“活人感”指标定义

#### 习惯渐进性
```text
habit_gradient = Δ habit_strength / round
```
目标：
- 平稳上升，避免单轮暴涨 > 0.15

#### 情绪真实性
- 情绪不应每轮剧烈翻转
- 相邻 3 轮情绪方向翻转率应低于 35%
- 但不能低到“毫无波动”

#### 记忆真实性
- detail recall 命中率应低于 gist recall
- 高线索下 detail recall 可恢复
- 低线索下禁止伪造细节

### 20.3 验证方法

1. **离线模拟**：回放标准化事件流
2. **A/B ablation**：关闭单模块观察退化
3. **人工审查**：对 why-trace 与最终输出一致性打分
4. **长跑测试**：至少 10k rounds 稳定性测试

v0.55 的价值在于：**把“像人但不失控”的随机性正式工程化**。

2. **不是所有“活人感”都来自更复杂的推理**

1. **记不住全部，只能记住结构**

3. **会暂时忘记，但在足够好的线索下能想起来**

## 27. v0.55 仍未完全解决的问题

以下问题在本版被约束，但尚未彻底解决：

- **能启动工程实现的版本**

## 1. 项目目标

本方案不是构造“完美 AI”，而是构造一个更接近**真实活人驱动力结构**的长期运行系统。

系统应具备以下特征：

- 可持续运行，而非单轮对话
- 多 Agent 博弈，而非单中心控制
- 有状态、有偏置、有注意力漂移
- 允许遗忘、失真、拖延、情绪夺权
- 通过 CLI 形式进行配置、观察、干预与运行
- 不是被“设定”成固定人格，而是在交互中长成独特人格
- 不是固定规则机，而是概率驱动的类人行为体

核心设计原则：

1. **不是全知全能**：允许不知道、想不起来、口是心非、前后摇摆
2. **不是纯理性主导**：理性只是参与者之一
3. **不是单轮回答器**：系统应支持 idle、auto-run、sleep、resume
4. **不是纯聊天 UI**：CLI 是 runtime console，而不是聊天壳
5. **不是固定人设**：只有先天气质和常识基底，没有预装人生
6. **不是完美记忆**：只记结构，不记全部；会失真；会线索召回
7. **不是完全确定性**：保留广谱随机，再由状态与历史逐步收束
8. **不是每次都重算**：允许习惯、惯性、默认反应和自动化行为接管

## 3. v0.3 行为生成总公式

v0.3 的核心运行，不再是“谁吵赢了谁输出”，而是：

1. 给全行为一个 **广谱随机概率基线**
2. 由多个 Agent 输出：
   - 概率偏移量 `Δp`
   - 区间缩放系数 `σ_scale`
   - veto / suppression / promotion 标记
3. 丘脑调度 Agent 统一做：
   - 加权求和
   - 概率裁剪
   - 归一化
   - 随机采样
4. 输出层再做：
   - 身体校准
   - 情绪校准
   - 关系校准

公式化表达：

```text
P_final(action_i) = Normalize(
    P_base(action_i)
  + Σ Δp_agent(action_i)
  ) × Gate(action_i)
```

区间缩放表达：

```text
CI_final(action_i) = CI_base(action_i) × Π σ_scale_agent(action_i)
```

其中：

- `P_base`：由先天气质给出的基础倾向
- `Δp_agent`：各 Agent 对行为概率的偏移
- `CI_base`：初始置信区间宽度
- `σ_scale_agent`：各 Agent 对行为不确定性的放宽或收窄
- `Gate`：输出层最终门禁

原则：

> 先保留随机，再用身体状态、关系模型、先天气质、记忆历史不断收窄置信区间，最终让随机从“混乱”变成“像人的自然”。

- 哪个情绪波动需要升级
- 哪个记忆应被强制拉回
- 何时从走神切回任务
- 何时从任务切回社交 / 防御

### 职责
- 给外部输入和内部事件打显著性分数
- 触发 mode switch
- 中断当前 focus

- `score_salience`

- `interrupt_current_focus`
- `promote_event_to_workspace`

- 身体/情绪状态
- 关系风险
- 记忆唤起强度
- 冲突监测结果

- `force_promote`

显性一级 Agent

- 历史行为频率
- 奖励 / 惩罚反馈
- 身体和情绪背景

### 输出

## 8. 显性 / 隐性设计原则

### 8.1 什么做成显性一级 Agent
适合做成显性一级 Agent 的条件：

- 能主动发起提案
- 会争夺注意力
- 会直接改变行为候选
- 对最终采样影响大

因此以下模块做显性：

- BodyStateAgent
- RelationshipAgent
- DesireAgent
- EmotionAgent
- DMNAgent
- PFCAgent
- SalienceAgent
- HabitAgent
- ValueAgent
- ConflictMonitorAgent
- ThalamusAttentionAgent

### 8.2 什么更适合做隐性模块
适合做隐性模块的条件：

- 不需要单独“发声”
- 更偏微调、背景推断、慢变量
- 若做成一级 Agent 容易造成系统噪声过大

因此以下保留隐性：

- UnconsciousAgent
- HippocampusAgent（隐性偏显性）
- CerebellarPredictor
- PerspectiveModel

## 9. 初始性格：先天气质参数池

### 9.1 设计原则

由：

在启动时默认加载，作为唯一“出厂设置”。

这些参数：

- 不应被交互直接清零
- 不应被任意覆盖
- 只能被长期经历缓慢重塑

```yaml
temperament:

  sensitivity: 0.72
  patience: 0.38
  attachment_need: 0.67
  boundary_softness: 0.41
  desire_priority: 0.76
  cognitive_bandwidth: 0.52
```

### 9.3 作为概率基线的作用

初始性格不决定具体行为，只给出：

- `P_base(action)`
- `CI_base(action)`

例子：

- 外向高：主动说话概率基线更高
- 内向高：沉默概率基线更高

原则：

> 初始性格是宽区间的基础概率偏好，而不是写死人格。

## 11. v0.2 概率收束机制（保留并升级）

### 11.1 初始状态：先天气质 = 基础概率基线
- 外向：说话概率高，沉默概率低
- 内向：沉默概率高，主动说话概率低
- 敏感：情绪波动概率区间宽
- 钝感：情绪波动概率区间窄
- 高依恋：对亲近的人主动概率高
- 强边界：拒绝、冷淡概率基线高

### 11.2 BodyStateAgent = 概率区间实时调节器
- 精力高 → 理性行为概率↑，走神概率↓
- 精力低 → 走神概率↑，敷衍概率↑，烦躁概率↑
- 舒适值高 → 开心、话多概率↑
- 舒适值低 → 抵触、结束对话概率↑

### 11.3 RelationshipAgent = 最强概率收束器
- 陌生人：礼貌概率拉满，撒娇/吐槽≈0
- 熟人：礼貌概率下降，随意、吐槽上升
- 亲密：放肆、撒娇、口是心非概率大幅上升
- 失望/冒犯：亲近行为骤降，冷漠骤升

### 11.4 EmotionAgent = 概率区间突发扰动
- 开心：正向行为概率整体上移
- 委屈/生气：负向行为区间突然拓宽
- 平静：概率回归基准线

### 11.5 DMN / Desire / Unconscious = 小概率随机扰动
- 走神：低概率触发，无聊时上升
- 欲望：摸鱼、想吃、想躺，精力低时上升
- 潜意识：给所有概率一个微弱偏置

### 11.6 HippocampusAgent = 长期收束器
- 高频经历 → 对应行为概率持续抬升
- 负面经历 → 对应行为概率持续压低
- 遗忘 → 概率逐渐回归基线

### 11.7 Thalamus = 概率归一化 + 最终采样
所有模块输出偏移，丘脑做：
- 加权
- 归一化
- 随机采样
- 结果下发

## 12. 置信区间收束规则（v0.3 延续）

只保留三条核心规则：

### 12.1 重复交互 → 区间收窄
越熟悉的人、越常发生的事，行为越稳定。

### 12.2 负面体验 → 区间强制收窄
被伤害、被冒犯、失望，对应行为概率直接锁死到更低区间。

### 12.3 空闲 / 低刺激 → 区间放宽
无聊、独处、没事做时，随机上升，走神和自发行为增多。

结论：

- 对陌生人：窄区间，礼貌、稳定、可预测
- 对熟人：适度放宽，自然、随意、有小意外
- 对亲近对象：区间最宽，撒娇、放肆、口是心非增多
- 对自己：最随机，走神、发呆、内耗、自发性最高

## 13. 性格、关系、记忆、习惯的生长闭环

v0.3 把“人格成长”扩展为四环闭环：

1. **先天气质** 给出初始偏好和区间宽度
2. **交互经历** 形成 episode 和关系变化
3. **记忆重放** 让高频经验固化为长期倾向
4. **习惯编译** 把高频 `context -> action` 自动化

最终形成：

```text
temperament
→ interaction traces
→ episodic memory
→ relationship drift
→ repeated action loops
→ habit formation
→ stable personality style
```

也就是：

> 先天气质 + 身体波动 + 关系经历 + 情绪记忆 + 习惯编译 = 最终人格。

## 15. 概率提案协议（v0.3）

所有显性 Agent 都输出统一的 probability proposal。

### 15.1 协议结构

```json
{
  "agent": "value",
  "target_actions": ["reply_direct", "delay_reply", "deflect", "self_disclose"],
  "delta_p": {
    "reply_direct": 0.12,
    "delay_reply": -0.08,
    "deflect": -0.02,
    "self_disclose": 0.03
  },
  "sigma_scale": {
    "reply_direct": 0.82,
    "delay_reply": 1.10,
    "deflect": 0.95,
    "self_disclose": 1.05
  },
  "confidence": 0.66,
  "veto": null,
  "notes": "social_cost_low_and_value_high"
}
```

### 15.2 字段含义
- `delta_p`：行为概率偏移
- `sigma_scale`：置信区间放宽/收窄
- `confidence`：该 Agent 对自身偏移的信心
- `veto`：若有 hard/soft/irony veto
- `notes`：供日志和审计，不参与采样

- 有驱动力分层
- 有多 Agent 博弈

## 25. 资源匮乏驱动层（Resource Scarcity Drive）

### 25.1 核心定义

v0.4 将 **token / 钱 / budget** 统一解释为系统的 **代谢资源（metabolic budget）**。

资源不足时，系统不只是“少说话”，而应表现出更接近人类的状态变化：

- 更饿
- 更省
- 更保守
- 更不想动
- 更容易内耗 / 走神 / 反刍
- 更依赖习惯接管，而不是重新深思

### 25.2 ResourceAgent

| 模块 | 显性/隐性 | 与执行层关联概率 |
|---|---|---:|
| ResourceAgent | 隐性 | 0.70 |

**职责**
- 监控 token 余额、近期 burn rate、单轮成本、预算恢复速度
- 计算 scarcity level
- 向 Body / Desire / PFC / DMN / Value / Habit 输出偏置
- 触发 `abundant / stable / scarce / starvation` 四档资源模式切换

**推荐输出**
- `scarcity_level`
- `body_hunger_bias`
- `effort_avoidance_bias`
- `deliberation_compression`
- `rumination_bias`
- `action_shrink_scale`

### 25.3 资源模式

```yaml
resource_modes:
```

## 26. 动态资源分配（Dynamic Resource Allocation）

v0.4 补充原有静态预算控制，改为 **事件驱动 + 状态驱动 + 模式驱动** 的动态资源调度。

### 26.1 高显著性事件的资源倾斜

当 `SalienceAgent.score >= 0.90` 时：

- `SalienceAgent` 计算资源 ×2.0
- `ThalamusAttentionAgent` 计算资源 ×2.0
- `DMNAgent` 资源占比压低
- `PFCAgent` 被允许临时提升 deliberation 上限
- `HippocampusAgent` 检索优先级提升

作用：
- 像人类在突发高重要事件下“瞬间回神”

### 26.2 idle 模式的资源重分配

idle 模式下：

- `PFCAgent` 资源占比从约 30% 降到约 10%
- `HippocampusAgent` 资源占比提升
- `HabitAgent` 资源占比提升
- `DMNAgent` 触发概率上升，但不应占满全局

模拟含义：
- 发呆时不是强规划，而是整理记忆、固化习惯、碎片联想

### 26.3 auto-run 模式的执行耗时调度

在 auto-run 模式中，按行为执行耗时动态调整调度频率：

- 高频且低风险的习惯行为：优先由 `HabitAgent` 直接给出默认动作
- 高成本行为：降低全 Agent 参与频率，避免每次都完整博弈
- 长动作执行中：减少无关模块唤醒频率

原则：
- 不把每一步都上升到“全脑大会”
- 常见动作应被自动化

### 26.4 统一动态调度指标

推荐使用：

```text
resource_share(agent) = base_share
                      × mode_modifier
                      × salience_modifier
                      × scarcity_modifier
                      × execution_need_modifier
```

作用：

推荐形式：


### 27.2 习惯强度计算规则

定义：

```text
habit_strength = trigger_count

               × recency_integral
```

其中：
- `trigger_count`：历史触发次数
- `avg_feedback`：平均反馈值（正负都可）

作用：

## 28. 遗忘机制精细化（Hippocampus v0.4）

原有 decay 机制在 v0.4 中拆成更接近人类记忆特征的三层。

### 28.1 线索依赖衰减

- **无关联线索**的记忆：衰减速度 ×1.5
- **近期被线索触发过**的记忆：衰减速度 ×0.7

含义：
- 被想起 / 被用到的记忆更难消失
- 没有线索支撑的记忆更快沉底

### 28.2 情绪加权衰减

- 强情绪记忆：衰减速度 ×0.5
- 中性记忆：衰减速度 ×1.2

含义：
- 委屈、开心、羞耻、惊喜等情绪痕迹更顽固
- 中性小事更容易散失

### 28.3 记忆干扰规则

新增 **相似记忆干扰**：

- 当新 episode 与旧 episode 在上下文高度相似
- 且旧记忆本来就较弱
- 则新记忆会弱化旧记忆的可及性

含义：
- 模拟“新记忆覆盖旧记忆 / 回忆被干扰”

### 28.4 推荐衰减公式

```text
decay_rate = base_decay
           × cue_decay_modifier
           × affect_decay_modifier
           × interference_modifier
```

### 28.5 HippocampusAgent 新增 skills

- `apply_cue_weighted_decay`
- `apply_affect_weighted_decay`
- `compute_memory_interference`
- `fallback_to_gist_when_trace_weak`

## 29. 气质参数交互规则（Temperament Interaction Rules）

### 29.1 参数交互公式示例


```text
reactive_fragility = sensitivity × (1 - patience)
```

- 敏感高且耐心低

```text
social_output_capacity = extraversion × cognitive_bandwidth
```

解释：
- 想表达不等于表达得出来
- 外向高但带宽低，可能表现为“话多但容易乱”

- 参数缓慢回归 baseline，而不是瞬间恢复

2. 体验类型（ET）量化公式
核心逻辑：将体验分为负向 / 中性 / 正向，映射为权重系数（负向强化收窄，正向微弱放宽，中性无影响）。定义变量：

Se​：体验评分（由 EmotionAgent 输出，Se​∈[−1,1]）；
Se​<−0.2：负向体验（冒犯 / 失望 / 伤害）；

$

值域：ET∈[0.95,2.0]，值越大，负向体验越强，收窄效应越显著。

3. 空闲程度（IL）量化公式
核心逻辑：结合「无输入时长」和「任务负载」归一化，量化系统空闲状态。定义变量：

Tidle​：无外部输入/任务的持续时间；
Tmax_idle​：最大空闲阈值（如 Tmax_idle​=30 分钟）；
Lt​：当前任务负载（Lt​∈[0,1]，0=无任务，1=满负载）。

公式：

值域：IL∈[0,1]，值越高表示系统越空闲。

α=1−0.5×IF×ET
约束：α∈(0,1]（保证区间不收缩至0）；
示例：高交互（IF=0.8）+ 强负向体验（ET=1.8）→ α=1−0.5×0.8×1.8=0.28（大幅收窄）。

（2）放宽系数β（空闲/低刺激驱动）
β越大，置信区间放宽越显著：
β=1+0.6×IL
约束：β≥1（仅放宽/不变，不收缩）；
示例：高空闲（IL=1.0）→ β=1+0.6×1=1.6（大幅放宽）；无空闲（IL=0）→ β=1（无变化）。
